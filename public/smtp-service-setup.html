The companion service connects securely to your SMTP providers, processes launched campaigns in the background and serves unsubscribe links to recipients.

Download SMTP service packageOpen email marketing
Deployment is required for live email. The private Trezad workspace is hosted separately. Install this service on a server with SMTP network access, then enter its URL in Sending setup. The download contains source and installation files; it contains no saved credentials or contacts.
01 / PREPARE A HOST

A server, a hostname and HTTPS

Use a server with Docker Compose, a persistent disk and outbound access to your SMTP provider. Point a dedicated hostname at it, such as mail-relay.your-domain.com.

  • Inbound ports 80 and 443 must reach the supplied HTTPS proxy.
  • Outbound SMTP ports default to 465, 587 and 2525.
  • Keep the service database on its persistent Docker volume.
02 / CONFIGURE AND START

Install the service package

Extract the download and open its smtp-relay directory on the server.

cp .env.example .env

Edit .env. Use your real hostname and two different random secrets.

SMTP_RELAY_HOST=mail-relay.your-domain.com
SMTP_RELAY_PUBLIC_URL=https://mail-relay.your-domain.com
SMTP_RELAY_TOKEN=<your random API token>
SMTP_RELAY_SIGNING_KEY=<a different stable random secret>

Generate each secret locally with:

node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

Then start the service and HTTPS proxy:

docker compose up -d --build

Caddy provisions the HTTPS certificate. Keep .env, the signing key and the database private. The full deployment and backup guide is included as DEPLOYMENT.md.

03 / CONNECT YOUR WORKSPACE

Save the service and your accounts

  1. Open Email marketing → Sending setup.
  2. Save the service HTTPS URL, its API token and your business postal address.
  3. Select Test service.
  4. Open SMTP accounts, add an account, then Test connection and enable it.
  5. Repeat for the accounts you want available. Choose the rotation pool separately when launching each campaign.

Saved passwords and tokens are encrypted. A connection test authenticates without sending a message. The campaign's single-address test checks the actual sending path.

04 / ENABLE BACKGROUND DELIVERY

Keep sending when the browser closes

The companion includes an independent campaign queue runner. Configure the following deployment secrets using the supported Site service-access setup:

TREZAD_SITE_URL=<your private Trezad Site origin>
SITE_PLATFORM_TOKEN=<current Site service-access token>
MARKETING_WORKER_TOKEN=<token matching the configured worker fingerprint>
SCHEDULER_INTERVAL_MS=1000

The app uses EMAIL_WORKER_TOKEN_SHA256 as the protected worker fingerprint. Set the matching token in the companion; keep it out of source and browser code. Optional EMAIL_WORKER_TOKEN also advances the existing mailbox verifier.

Restart the service after changing deployment variables. Check the Background processing heartbeat in Sending setup. The campaign's own interval and account limits control when emails are actually submitted.

Before the background worker is connected

An open, visible email workspace can advance launched campaigns through the deployed SMTP service. Closing the page stops that fallback. The separate hourly verifier task checks email lists and does not send campaigns.

Your first campaign

  1. Complete an email-verification job.
  2. Import its Valid results into a named contact group.
  3. Choose a template, edit the HTML and save a draft.
  4. Send a test to the mailbox you enter.
  5. Select groups, SMTP accounts and an interval, then launch.

What a result means

Accepted means the SMTP provider accepted the message. It does not prove inbox delivery.

Unknown means the response was uncertain. The app stops automatic retries to prevent duplicate mail.

Use your provider's sender authentication and account limits. SMTP accounts that require OAuth-only sign-in need compatible credentials or an additional OAuth integration.
